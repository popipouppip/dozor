# ДОЗОР

Фоновый агент Лёни. Живёт в Планировщике заданий Windows, будит Claude Code по расписанию и общается с Лёней через Telegram-бота «Сводка» (@news_leonidbot).

Скрипты только собирают факты. Смысл, отбор и формулировки — работа Claude, который эти факты читает.

## Что делает

| Когда | Задача | Что происходит |
|---|---|---|
| Каждый день 6:30 | `DOZOR` | Утренняя сводка: 22 источника, дедлайн, пять слов китайского. Стоящее откладывает в базу знаний |
| Каждые 10 минут | `DOZOR-Chat` | Проверяет, не написал ли Лёня боту. Если написал — будит Claude, тот отвечает |
| Воскресенье 20:00 | `DOZOR-Week` | Итоги недели: что сделано, где стоим, что горит до 1 сентября |
| Среда 20:00 | `DOZOR-SHOS` | Ищет свежую фактуру для научной статьи, складывает в `shos-article/nahodki.md` |
| Каждый день 6:27 | облачная routine | Короткая сводка из облака: работает даже при выключенном компьютере, приходит уведомлением на телефон |

Claude просыпается только когда есть работа: проверка сообщений — обычный Node, дешёвая и быстрая.

Сторож сайтов (`DOZOR-Watch`, `watch.js`) убран 02.09.2026 — Лёне не нужны сообщения о том, живы ли сайты и за сколько миллисекунд ответили.

## Два ДОЗОРа, домашний и облачный

Домашний — основной: у него есть все 22 ленты и доступ к папкам проектов, пишет в Telegram. Но он живёт в Планировщике Windows, поэтому работает только когда компьютер включён.

Облачный (`zadacha-cloud.md`) — страховка на выключенный компьютер. Запускается сам в облаке Anthropic и присылает уведомление на телефон. Его среда сильно урезана, и это не обходится:

- `curl` и `fetch` из песочницы закрыты — 403 «Host not in allowlist»;
- `api.telegram.org`, сайты на `vercel.app` и все RSS-ленты закрыты egress-прокси даже для WebFetch;
- открыты только WebSearch и WebFetch на github.com.

Отсюда и разделение: материал ищется поиском, а вместо письма в Telegram уходит push-уведомление, полный текст остаётся в сессии.

## Почему домашний ДОЗОР молчит: всё упирается в VPN

И Anthropic, и Telegram у нас доступны только через VPN (Koala Clash). Пока он выключен, не работает ничего: Claude отвечает `403 Request not allowed`, а node — `fetch failed`.

Первая починка (21.08) научила `run-task.ps1` ждать сеть 25 минут. Этого не хватило: 2 сентября задача ждала с 20:00 до 20:25 и сдалась, а Лёня включил VPN в 20:28. Что сделано 02.09:

- `run-task.ps1` сам поднимает VPN — `schtasks /run /tn koala-clash-run` (работает без прав администратора) — и повторяет попытку каждые 30 минут;
- ждёт сеть не 25 минут, а до 6 часов: поздняя сводка лучше, чем никакой;
- у задач `DOZOR`, `DOZOR-SHOS`, `DOZOR-Week` выставлены `MultipleInstances = IgnoreNew` и лимит 8 часов, чтобы ожидающие запуски не накапливались;
- `chat.js` при обрыве сети выходит тихо (код 2), а не роняет в лог красный стек каждые 10 минут.

Осталось вручную: добавить Koala Clash в автозапуск Windows — тогда сеть будет готова к 6:30 и ждать не придётся.

## Управление

```powershell
Get-ScheduledTask -TaskName DOZOR*                    # все задачи и их состояние
Start-ScheduledTask -TaskName DOZOR                   # прислать сводку прямо сейчас
Disable-ScheduledTask -TaskName DOZOR-Chat            # выключить ответы бота
```

Вручную: `powershell -File run-task.ps1 -Task nedelya`. Ход работы — в `dozor.log` и `chat.log`.

## Настройка источников — `sources.json`

| Тип | Поля | Где взять |
|---|---|---|
| `youtube` | `handle` (`Fireship`) **или** `channelId` | Хэндл из адреса канала — ID агент найдёт сам |
| `github` | `repo` (`owner/name`), `kind` (`releases`/`commits`) | Из адреса репозитория |
| `telegram` | `channel` (без `@`) | Имя публичного канала |
| `rss` | `url` | Ссылка на RSS/Atom |

Дополнительно: `topic` — тема для группировки, `days` — своё окно в днях для редких тем вроде грантов.

Ни один источник не требует ключа или регистрации. Можно и просто написать боту: «добавь источник такой-то» — агент сам поправит файл.

## Почему не в облаке

Сначала это делал облачный агент по расписанию. Расписание создавалось, но сессии не запускались: без подключённого к аккаунту GitHub облачной среде нечего разворачивать, и запуск гас молча — не доходил даже пинг первой строкой. Vercel как запасной путь отпал: платформа не отдаёт значения секретов обратно.

Локальный запуск оказался и проще, и лучше: письма пишет Claude, а не модель попроще, секреты никуда не уезжают, а «запустить при первой возможности» закрывает случай выключенного компьютера.
